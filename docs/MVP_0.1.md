# MVP 0.1 — Interactive abstract dynamics

**Status:** Deployed to GitHub Pages. Native Rust CI and the WebAssembly Pages build have passed for the current implementation.

## Purpose

Provide the first usable, public, end-to-end experiment surface. This MVP demonstrates configurable abstract dynamics and read-only observation. It does **not** claim to demonstrate evolution, inheritance, selection or adaptation.

## Included

- Rust simulation core compiled to WebAssembly.
- Browser interface hosted on GitHub Pages.
- Configurable initial entity count and random seed.
- Two continuous scalar state channels per entity.
- Local, distance-weighted pairwise exchange.
- Stochastic perturbation.
- Periodic 2D positions with channel-dependent movement.
- Pause/run, fixed-step execution, reset and deterministic 100-step replay.
- Read-only summary metrics and diagnostic state hash.
- Exportable schema-v1 JSON run manifest generated by the Rust runtime, recording seed, model, parameters, conflict policy, PRNG and stream scheme, initial and terminal state hashes, build commit and replay hash.
- Versioned append-only event log containing the initial snapshot and every committed proposal batch.
- In-browser replay verification and event-log JSON export.
- CI validation of native Rust and browser WebAssembly builds.

## Model definition

Each abstract entity has an explicit substrate identity, a 2D coordinate and two scalar state values in [0, 1]. The world is periodic in both spatial dimensions. For each transition, every pair within the configured interaction radius exchanges a fraction of the difference between each scalar channel. The exchange weight decreases linearly with squared distance. Independent pseudorandom perturbations are applied to both channels. The resulting channel values influence small positional displacements. There is no creation, retirement, duplication, fusion, fitness, lineage, environmental resource field or reproduction mechanism in this MVP.

This is intentionally a narrow dynamics testbed, not a substitute for the complete specification. The initial implementation uses an O(n²) pair scan. The browser runtime caps the initial population at 500 to keep the quadratic pair scan practical on mobile devices.

## Reproducibility scope

The random stream is deterministic for the same compiled runtime, seed and execution path. The browser experiment now runs its state changes through the general entity/property substrate and records each committed proposal batch in the versioned event log. The interface exposes replay verification, event-record counts and full event-log export. The exported manifest is generated by the Rust runtime and follows [RUN_MANIFEST.md](RUN_MANIFEST.md). It includes the deployed build commit, initial state hash, random generator and actual stream-consumption scheme, parameters, conflict policy, terminal hash and replay hash. The current browser model uses a single sequential SplitMix64 stream and the default reject conflict policy. Cross-version, cross-browser and cross-architecture bitwise reproducibility are not claimed. The hash is a diagnostic checksum, not a cryptographic integrity mechanism.

The replay control reconstructs the initial state from the displayed seed and settings and runs exactly 100 transitions. The verify control replays the recorded proposal batches from the versioned initial snapshot and compares the resulting state hash with the live state. Changing parameters after a run changes the live model settings; reset is required to apply a new initial population or seed.

## Run locally

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
wasm-pack build --target web --release --out-dir site/pkg
python -m http.server 8000 --directory site
```

Open http://localhost:8000. A local HTTP server is required because browser module loading does not work from file://.

## MVP exit criteria

- Native Rust tests pass.
- wasm-pack build succeeds for wasm32-unknown-unknown.
- Pages build and deployment complete.
- Live page loads the generated WASM module.
- Run, pause, step, reset, replay and manifest export controls work.
- Same seed/configuration/replay path produces the same terminal state hash.
- Limitations are visible to users and no evolutionary claims are made.

## Next scientific work

1. Extend the general runtime beyond property updates with generic entity/relation creation, retirement, endpoint changes and explicit transformation constraints.
2. Add environment fields and resource accounting as configurable model modules.
3. Add a headless experiment runner using the shared run-manifest format and controlled multi-seed trials.
4. Add observational measurements for persistent configurations and repeatable state transfer.
5. Only then investigate candidate inheritance and differential propagation.
