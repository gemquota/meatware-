# Maintainer Handbook

## Daily triage
1. Check new issues, comments, PRs and task claims.
2. Acknowledge useful submissions; do not leave contributors guessing.
3. Apply status labels where available.
4. Link duplicates to the canonical task.
5. Identify scope, rights, safety or canon blockers.
6. Update the task board only when actual state changes.

## Submission states
Open → Claimed → Submitted → In review → Accepted / Revision requested / Rejected

- **Open:** available; no active claim.
- **Claimed:** contributor stated intent; this is coordination, not ownership.
- **Submitted:** material arrived.
- **In review:** reviewer is actively checking it.
- **Revision requested:** specific changes needed.
- **Accepted:** criteria met and approved for integration.
- **Rejected:** not accepted; provide a concise reason.
- **Blocked:** cannot proceed until a named dependency is resolved.
- **Superseded:** another accepted artifact replaces it; preserve history.

## Response targets
- Acknowledge a first contribution within 72 hours where practical.
- Give substantive first review within seven days.
- If review capacity is unavailable, say so and set expectations.
- Do not recruit faster than the project can review.

## Review checklist

### Scope
- Does it answer the task?
- Is the output complete and at the right level?
- Are acceptance criteria demonstrably met?

### Story and canon
- Are established facts preserved?
- Are proposals labelled?
- Are continuity conflicts raised?
- Does the contribution preserve the characters' comic mechanism?

### Originality and provenance
- Is the work original or properly attributed/licensed?
- Does it avoid copied dialogue, lyrics, scripts and unlicensed assets?
- Are source facts distinguished from new material?
- Is meaningful AI assistance disclosed?

### Production utility
- Can the next pipeline stage use it?
- Are directions concrete and testable?
- Are costs, assumptions and dependencies visible?

### Contributor care
- Is attribution correct?
- Is feedback specific and respectful?
- Is the next step clear?

## Acceptance procedure
1. Comment with the review decision.
2. Request revisions with numbered, testable points.
3. Merge or copy accepted work into its canonical path.
4. Update CREDITS.json only after credit policy approval and acceptance. Until then, record attribution in the issue/PR.
5. Update task board, agent manifest and relevant README when status or path changes.
6. Link the accepted artifact in the contributor's issue.
7. Offer one adjacent task, not a giant backlog.

## Conflict resolution
- Resolve factual disagreements using source material and provenance.
- Resolve canon disputes through the project editor and a recorded decision.
- Resolve credit disputes by preserving records and documenting adjustments.
- Escalate rights, privacy, harassment or safety concerns to the maintainer; pause publication if needed.
- Do not let an AI agent decide ownership, identity or final canon.

## Capacity rule
Keep no more active claimed tasks than can be reviewed. Close or pause stale tasks with an explanation. A small responsive project is healthier than a large unattended issue tracker.
