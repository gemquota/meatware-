## Claiming and submitting
1. Check the corresponding GitHub issue.
2. Comment Claiming TASK-ID.
3. Submit a draft in the issue or open a PR.
4. Include assumptions, canon conflicts, and self-check notes.

## Task status definitions
- **Open:** available to claim.
- **Claimed:** someone has stated they are working on it; not exclusive until maintainer confirms.
- **In review:** submission received.
- **Accepted:** meets the task and editorial criteria.
- **Blocked:** depends on an unresolved decision.
- **Closed:** completed, superseded, or intentionally cancelled.

## Add a task
A new task should have one clear output, a bounded scope, a self-contained prompt, acceptance criteria, target path, and a corresponding GitHub issue. Avoid vague tasks such as “improve the franchise” or “make it better.”
